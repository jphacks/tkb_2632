# ShotRelay — 最小動作版

相手を撮る → 写真が届く → 本人がお気に入りと理由を選ぶ → 撮った人が3択で予想 → 答え合わせ → もう一度撮る。

見た目より、スマートフォン2台でこの往復を完了できることを優先した試作です。

## 起動

Node.js 22以上を用意してください。外部サービスの登録・APIキー・依存パッケージのインストールは不要です。

```bash
git clone https://github.com/jphacks/tkb_2632.git
cd tkb_2632
git switch tanaka
npm start
```

PCで `http://localhost:3000` を開きます。停止は Ctrl+C。

## 2人で使う

1. 同じWi-FiのPCでサーバーを起動する。
2. スマホ2台から `http://PCのLANアドレス:3000` を開く（例：`http://192.168.1.10:3000`）。Windowsでは `ipconfig` のIPv4アドレスを確認。
3. それぞれ表示名を入力。一人が部屋を作り、相手が6桁コードで参加する。
4. 「カメラで撮る／写真を選ぶ」で撮影・追加する。端末によってカメラか写真選択が開く。連続して追加でき、一度に最大9枚。
5. 「写真を相手に送る」を押すと1セットとして送信。相手の画面には約2.5秒間隔で反映される。
6. 撮られた側が1枚を選び、任意の理由タグを付けて返す。
7. 撮った側が3択で予想。予想しないで結果を見ることもできる。
8. 結果と理由を参考にもう一度撮る。役割を交代しても同じ流れで使える。

3枚未満のセットでは予想ゲームを省略し、お気に入りと理由を直接表示します。4枚以上ではお気に入り1枚とその他2枚を無作為に選びます。お気に入りは最初の版では1セット1枚です。

PCだけなら、通常ウィンドウとシークレットウィンドウ、または別ブラウザで2人分を試せます。同じブラウザのタブ同士は同一ユーザーです。

接続できない場合は同じWi-Fiか、PCの受信設定でポート3000を許可しているか確認してください。ゲストWi-Fi等で端末間通信が禁止されていると接続できません。

## 実装済み

- 表示名でのブラウザ参加・2人限定の部屋・招待コード
- 写真選択／端末のカメラ呼び出し・送信前プレビュー・除外
- 最大辺1400pxに縮小しJPEGで送信
- 端末間の写真共有・お気に入り・理由タグ
- サーバーで正解を伏せた3択予想・答え合わせ・スキップ
- ペア参加者だけの写真閲覧
- 写真・結果のローカルファイル保存、サーバー再起動後の復元

## 今は入れていないもの

AI解析、撮影ガイド、カルテ、プッシュ通知、写真編集、アカウント引き継ぎ、ペア解除、写真削除、複数お気に入り、ストア配信。

写真の即時自動送信は行わず、本人が「送る」を押したセットを共有します。撮影画面のライブ映像は未実装です。写真選択の `capture` 指定で端末標準のカメラを呼び出す方式を採用し、HTTPのLAN接続でも実験を始めやすくしています。

## 保存・運用上の範囲

この版は同じネットワーク内の2人で試す開発用です。公開運用前にはHTTPS、正式な認証、招待コードの試行制限、写真削除・保存期間などを整備してください。

ブラウザの参加情報はHttpOnly Cookieです。Cookieを消すとその人として入り直せません。写真と状態はサーバーの `data/state.json` に保存され、Gitには含みません。サーバーを止めて `data/` を削除すると全員分の状態・写真が消えます。上書きや削除前は必要に応じバックアップしてください。サーバーの保存データへのアクセス権は運用者にあります。

## 検証

```bash
npm test
```

2人の参加、写真送信、お気に入り、正解の秘匿、3択、答え合わせ、役割交代、少数写真でのスキップ、ペア外の閲覧拒否、再起動後の復元をAPIテストで確認します。スマートフォン実機でのカメラ呼び出しと撮影写真の向きは、使用端末で別途確認してください。

## 構成

- `server.mjs`：Node.js標準HTTPサーバー、参加・共有・予想API、永続化

- `test/cycle.test.mjs`：一連の往復のテスト

将来Firebase等へ移す場合も、`/api/state`・`/api/rounds` 等の役割を維持しながら段階的に置き換えられます。
