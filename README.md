# ShotRelay — Flutter Web版

添付の「撮影体験の流れ」を基準に、ページを分けたFlutter Webフロントエンドを追加しました。

**この配布物はソースコードです。この制作環境ではFlutterの初期化がブロックされたため、Flutterビルド・Flutterウィジェットテスト・iPhone実機テストは未実施です。Dartファイルの構文確認（整形）とNodeサーバーのAPI・配信テストは実施済みです。**

## 画面の流れ

名前入力 → ペア登録 → ホーム → 撮影 → 送信完了 → ホーム

ホーム → 届いた写真／アルバム → お気に入り選択＋理由タグ → 相手の予想待ち

ホーム → 予想ゲーム → 答え合わせ → 次の撮影

ホーム → 撮影カルテ（公開済みのお気に入り理由の集計）

- コーラル色・白ベースで、図のホーム・アルバム・予想の構成を参考にしました。
- 更新中も名前・招待コード・選択中の写真や理由が消えないよう、入力状態と受信状態を分離しています。
- お気に入り選択は最初の版では1セット1枚。理由タグは任意・複数選択。
- 3枚未満は予想を省略。4枚以上はお気に入り1枚＋その他2枚から3択を作成。
- 撮った側に正解や理由を公開するのは、予想またはスキップ後です。
- 最初は「撮る→相手へ送る→好き！を返す→予想→次に撮る」を優先。自動解析・白枠ガイドは未実装です。

## いまのプロジェクトに入れる

ZIP内の `ShotRelay` の中身を、いまの `tkb_2632/ShotRelay` にコピーします。

既存の `data` フォルダは消さないでください。このZIPには参加者・写真データを入れていないので、同じ場所のサーバーを使えば、今までのデータを利用できます。バックアップを取ってから上書きしてください。

## Windows / VS Codeで起動

必要：Node.js 22以上、Flutter stable（Dart 3.8以上を含む版）、Git。

Flutter SDKが未導入なら、公式手順でWindowsへ導入し、VS Codeを開き直してください。
https://docs.flutter.dev/install

PowerShellで、**package.jsonとserver.mjsがあるShotRelayフォルダ**へ移動します。

```powershell
cd C:\Users\tnkro\Documents\tkb_2632\ShotRelay
flutter doctor
npm run build:flutter
npm start
```

`npm run build:flutter` は、依存解決 → 静的解析 → ウィジェットテスト → Flutter Webビルドを順番に実行します。初回はダウンロードに時間がかかります。途中の処理が失敗した場合はそこで止まります。

ビルド済み画面とAPIを同じNodeサーバーから配信します。PCは `http://localhost:3000`、iPhoneは同じネットワークのPCのIPv4アドレス（例：`http://10.10.1.155:3000`）を開いてください。PCのアドレスはネットワークによって変わります。

会場Wi-Fiが端末間通信を遮断している場合は、PCとiPhoneが通信できるネットワークかHTTPSで公開したサーバーが別途必要です。Flutterへの移行だけでは通信制限は解消しません。

**`flutter run -d chrome` は今回の起動方法ではありません。** Cookieと写真APIを同じオリジンで扱うため、上記のビルド→`npm start`で動かします。

Flutter Webの画面を変更したときは、もう一度 `npm run build:flutter` を実行してから、`npm start`を再起動してください。

Flutterのビルドがまだない場合、`npm start`は旧HTML版を表示します。Flutter版と勘違いしないよう注意してください。Flutterビルド後も旧版は `/legacy` から開けます。

## iPhoneでの利用

1. SafariでサーバーのURLを開く。
2. 2人が名前を入力。一人が招待コードを作り、もう一人が同じコードで参加。
3. ホームの「撮影をはじめる」を押す。
4. カメラボタンで標準カメラを開くか、写真選択ボタンから既存写真を選択。
5. 「相手に送る」でまとめて送信。相手は「届いた写真」から選択・返答。
6. 撮った側のホームに予想ゲームの案内が表示される。

カメラ呼び出しの動作はSafariのバージョンに依存します。カメラが開かない場合は写真選択でテストしてください。HEIC等を読み取れない場合は標準カメラで撮り直すかJPEG・PNGを使ってください。

Safariの共有メニューから「ホーム画面に追加」できます。アプリアイコン・Webマニフェストを用意していますが、オフライン動作には対応していません。Safariとホーム画面起動でCookieが共有されない場合は、利用するほうで最初からペアを作ってください。

## ディレクトリ

- `flutter_app/lib/main.dart`：アプリテーマ、ホーム、ペア、アルバム、お気に入り、予想、答え合わせ、カルテ
- `flutter_app/lib/capture.dart`：写真撮影・選択・圧縮・送信
- `flutter_app/lib/controller.dart`：状態管理と定期更新
- `flutter_app/lib/browser_gateway.dart`：Cookieを保持したWeb API通信
- `flutter_app/lib/api.dart` / `models.dart`：通信インターフェース・データ型
- `flutter_app/web`：Web起動・ホーム画面アイコン
- `scripts/build-flutter.mjs`：Windows/macOS/Linux共通のビルド手順
- `server.mjs`：APIとフロントエンド配信
- `public/`：旧HTML版（名前入力が消える不具合を修正）

## 保存と利用範囲

同じネットワーク内で試す開発用です。データは `data/state.json` に保存され、Gitには含めません。ブラウザはHttpOnly Cookieで参加者を識別します。Cookieを消すと入り直せないため、動作確認時は利用ブラウザを固定してください。

公開運用前にはHTTPS・正式な認証・招待コード試行制限・写真削除・保存期間などの整備が必要です。サーバー管理者は保存ファイルへアクセスできます。
